## Data (ESPN)

| Date | Decision | Why |
|------|----------|-----|
| 2026-10-22 | The app has its own stat vocabulary (`lib/stats.ts`). Each data provider translates into it. | Scoring and UI never depend on ESPN's field names, so a provider can be swapped. |
| 2026-10-22 | ~~Phase 1 waits for real ESPN samples (ESPN blocked by the dev environment).~~ Unblocked once the owner allowed ESPN's hosts; real responses are saved in `samples/`. | Look before you build. |
| 2026-10-22 | **Provider interface** (`lib/providers/types.ts` `DataProvider`), ESPN implementation in `lib/providers/espn/`, and `lib/providers/index.ts` exports the active one as `sports`. App code never touches ESPN URLs directly. | Plan §4.1; a paid provider can replace ESPN in one line. |
| 2026-10-22 | Endpoints used: site `scoreboard` and `summary` (game header, drives, box score, win probability, odds), **core API `plays`** (play-by-play with participants and roles), site `teams`, `injuries`, fantasy `players_wl` (all players, for search), fantasy `kona_player_info` (injury status, weekly stats, projections, outlook text), fantasy `proTeamSchedules_wl` (bye weeks), fantasy news feed. | All verified with real calls; samples in `samples/`. |
| 2026-10-22 | **Per-player news uses ESPN's fantasy news feed** (`/apis/fantasy/v2/games/ffl/news/players?playerId=`), not `news?athlete=`. | The site news endpoint ignores its `athlete` filter (it returned general NFL news for Mahomes). |
| 2026-10-22 | Core API `$ref` links can point at an internal host (`sports.core.api.espn.pvt`); ids are extracted with a regex and never fetched. | Following those links fails from outside ESPN. |
| 2026-10-22 | ESPN fantasy stat ids, verified against the box score and ESPN's own PPR totals: 0 passAtt, 1 passCmp, 3 passYds, 4 passTd, 19 pass2pt, 20 passInt, 23 rushAtt, 24 rushYds, 25 rushTd, 26 rush2pt, 42 recYds, 43 recTd, 44 rec2pt, 53 rec, 58 targets, 72 fumLost (68 = all fumbles), 101/102 return TDs, 63 fumble-recovery TD (lower confidence). `leaguedefaults/3` = ESPN's default PPR league. | Projections and weekly stats come in these ids. |
| 2026-10-22 | **Play attribution** (`lib/providers/espn/stats/plays.ts`): stat changes per play come from the play type, participant roles and the play text. Rules: yards from the text, not `statYardage` (that's the team's net, 0 on fumbles lost, includes penalty yards); "No Play" counts nothing; replay reversals count only the post-reversal text; penalties enforced inside a gain cap the yards at the spot; fumbles lost = capital "RECOVERED by"; muffed punt lost = fumble lost; aborted snap = 1 carry 0 yards; interception = a target for the intended receiver; laterals credit both; 2-pt only when "ATTEMPT SUCCEEDS"; a blocked-punt TD is a D/ST TD, not a return TD. | Validated on all 14 Week 6 games: 264/268 players match the official box score exactly; total drift 0.2 PPR points. The 4 leftovers are official corrections not visible in the plays. |
| 2026-10-22 | **Official numbers win**: a player's headline points come from the box score (+ 2-point conversions from the plays, which box scores omit); per-play points are shown in the feed, and any gap is shown on the player card as an "official stat correction". | Plan §5.3. Matches ESPN's own fantasy totals on every tested player. |
| 2026-10-22 | **Live data without a worker:** API routes (`/api/scoreboard`, `/api/live`, `/api/games/[id]`, `/api/player/[id]`, `/api/players`, `/api/teams`) read ESPN through `lib/data/sports.ts`, which caches each call for all visitors with `"use cache: remote"` and custom `cacheLife` profiles (`live` 5 s, `final`, `outlook`, `reference` in `next.config.ts`). Phones poll every ~6–8 s while games are live, less otherwise, pause when hidden, and back off on errors while keeping the last good data ("Data delayed"). | Plan §3 allows this for early phases; ESPN load scales with games, not users. The worker (Phase 3) adds push updates and history on top. |
| 2026-10-22 | Live pages fetch at request time (`connection()`), never at build time. | A deploy must not fail (or bake in stale scores) if ESPN is slow during the build. |
| 2026-10-22 | Dark team colors (e.g. Houston navy) are swapped for the team's alternate color in rings and glows (`lib/color.ts`). | Otherwise they're invisible on the near-black background. |
| 2026-10-22 | Play text is cleaned for display: formation notes, tackler names, assist brackets and "reported in as eligible" notes are removed (`lib/live/play-text.ts`). | Plan §5.4. |

## Scoring engine (`lib/scoring`)

| Date | Decision | Why |
|------|----------|-----|
| 2026-10-22 | Presets match ESPN's default offense: 0.04/pass yd, 4/pass TD, −2/INT, 0.1/rush or rec yd, 6/rush or rec TD, 2/2-pt, −2/fumble lost, 6/return or fumble-recovery TD; receptions 0 / 0.5 / 1 for standard / half / PPR. Presets are frozen. | Plan §5.1; verified: our points equal ESPN's own PPR totals for real Week 6 players. |
| 2026-10-22 | `roundPoints` rounds to 2 decimals, halves away from zero, strips float noise, never returns −0. Totals are the rounded sum of exact values. | Avoids `0.30000000000000004`-style errors. |
| 2026-10-22 | Feed breakdowns keep up to 2 decimals ("+2.96 yds") while headline points show 1 ("+9.4"). | With 1 decimal, a 1-yard pass would read "+0 yds". |
| 2026-10-22 | `reconcile()` compares rounded drift to a 0.05 tolerance and always returns the **official** number as the headline. | Plan §5.3. |
| 2026-10-22 | **Kicker and D/ST scoring** uses ESPN's own default league settings (fetched from `leaguedefaults/3?view=mSettings`, saved in `samples/fantasy-league-defaults-scoring.json`; a test checks all 46 scoring items against our presets). K: FG <40 = 3, 40–49 = 4, 50–59 = 5, 60+ = 6, any miss −1, PAT 1 (a missed PAT costs nothing). D/ST: sack 1, INT 2, fumble recovery 2, blocked kick 2, safety 2, defensive/return TD 6, plus points-allowed tiers (0 → +5 … 46+ → −5) and yards-allowed tiers (<100 → +5 … 550+ → −7). Same in all three formats. | Verified: all 52 kickers and 52 D/STs in 26 real games, and 60 ESPN K/DST projections, match ESPN's official points exactly. |
| 2026-10-22 | Points- and yards-allowed **tiers are 0/1 stat keys** (`dstPa7_13`, `dstYa300_349`…). A play that moves a defense into a new tier is a normal stat change (`dstPa7_13: −1, dstPa14_17: +1`), so per-play points still add up to the total. A D/ST starts each game at +10 (0 points, 0 yards allowed). | Keeps the scoring engine linear and the feed honest about why a defense lost points. |
| 2026-10-22 | **ESPN's points allowed** = opponent's points minus 6 for each pick-six/fumble-return TD against your offense and minus 2 for each safety (the PAT after a pick-six still counts); punt-return and blocked-punt TDs count against you. Only sacks credited to a defender count. Kicker field-goal distances come from the play text (box scores have no distances). D/ST changes are computed per game (`defensePlayDeltas`), not stored on plays, so Game Center doesn't show nameless "Player" chips. | Matches ESPN's help page and all 24 such cases in Weeks 1–5. Unverified so far (not seen in real data yet): two-point returns, one-point safeties, blocked PATs. |

## Start/Sit advisor (`lib/startsit`)

| Date | Decision | Why |
|------|----------|-----|
| 2026-10-22 | The math decides; ESPN's projection is the base and every other factor is a small, capped nudge: matchup 25% of the defense's distance from average (cap ±8%, scaled down under 4 games), recent form 15% (cap ±6%), Vegas implied total 30% (cap ±6%), weather on passing positions only (rain −4%, snow −6%, wind −3%, ≤25°F −2%), all non-injury nudges together capped at ±18%. Injury: Questionable −10%, Doubtful −60%, Day-to-day −5%. Bye, no game, Out/IR/Suspended = 0 and an automatic sit. | ESPN's projection already accounts for most of these factors, so large weights would double-count them. |
| 2026-10-22 | **Defense vs. position** comes from the 500 most-owned players' weekly real stats plus the schedule; the provider returns stat totals only, and app code scores and ranks them (1 = toughest) per scoring format. Cached with the `outlook` profile. | The top 500 cover about 99% of fantasy points (the top 300 only about 91%). Verified: 2,765 weekly lines, totals equal ESPN's own PPR points. |
| 2026-10-22 | ESPN's `odds.spread` is from the home team's side (checked against `homeTeamOdds.favorite`). Implied team total = total/2 − (that team's spread)/2. | E.g. CHI −3 with a 50.5 total → 26.75. |
| 2026-10-22 | Weather comes from ESPN's forecast words plus temperature; there's no wind speed. Indoor stadiums get no weather effect. | That's all ESPN publishes. |
| 2026-10-22 | Floor/ceiling = score ∓ 0.85 × the expected weekly swing (about the 20th/80th percentile week); a Q or D tag widens it 25%. Confidence is the estimated chance the pick outscores the runner-up: ≥75% Strong, 62–75% Solid, below that Lean; never above Lean without an ESPN projection for either player; ties go to the higher floor. | Honest uncertainty, in words a new fan understands. |
| 2026-10-22 | **Back-test** (weeks 3–6, same-position pairs projected within 25% of each other): the model picked the higher scorer 55% of the time (PPR, 4,050 pairs), same as "higher ESPN projection" (55%). Confidence was calibrated (Lean right 54%, Solid 62%). Weights were **not** tuned to this data. | No hidden edge is claimed; the value is the explanation and the calibrated confidence. Injuries and Vegas lines aren't available for past weeks, so they weren't part of the test. |
| 2026-10-22 | Kickers and D/ST aren't in Start/Sit yet. Their scoring now exists, so they can be added next. | Defense-vs-position and the back-test only cover QB/RB/WR/TE. |
| 2026-10-22 | The picked players live in the URL (`?ids=`); the format switch on this screen doesn't change the saved roster. Server-written notes give kickoff times in ET; the cards show local time. | Shareable links; the server doesn't know the viewer's time zone. |
| 2026-10-22 | **AI explanation (optional):** only with `ANTHROPIC_API_KEY` set, through the official `@anthropic-ai/sdk`, with model `claude-opus-5-5` at low effort and server-side refusal fallback on. Claude sees only the structured facts and explains the decision; it never makes it. The reply is thrown away if it uses a number we didn't send or doesn't name the pick. One cached answer per distinct decision; failures are remembered for 60 s. The screen asks for it in a second request, so the numbers never wait for it. | Grounded, cheap, and the screen works the same without it. About a cent per new decision; switching `AI_MODEL` to `claude-haiku-5-5` would cut that to a fraction of a cent. |
| 2026-10-22 | `getDefenseVsPosition` is a required provider method. | App code never talks to ESPN directly. |

## Saved data

| Date | Decision | Why |
|------|----------|-----|
| 2026-10-23 | **One versioned storage helper** (`lib/storage/persisted.ts`) for everything saved on the device. Keys are now `fantasylab:*`. Old `the-feed:*` keys are read once and copied, and the old copy stays as a backup. Unreadable data is copied to `<key>:unreadable:<time>` before defaults are used, never deleted. A damaged roster entry is dropped on its own instead of losing the whole team. Tabs stay in sync. | Owner reported the team disappearing. A bug or a format change must never wipe a team. |
| 2026-10-23 | **No "empty team" screen before saved data is read.** Screens show their loading layout until `ready`. The team name saves as you type (it used to save only when you left the field). | The server-rendered empty state flashed on every load and looked like the team was gone. |
| 2026-10-23 | **Team links** (`/team/import?t=…`, `lib/roster/share.ts`): ids, slots, name and scoring packed into a URL. Settings explains that each web address keeps its own saved data, and that iPhone Safari clears sites unused for 7 days (Home Screen apps are exempt). Settings can also ask the browser to keep data (`navigator.storage.persist`). | Every Vercel preview URL is a separate origin with its own storage, which is the likeliest reason a saved team "disappeared". |
| 2026-10-23 | **Settings store** (`lib/settings/store.ts`): league size (8–16, default 12), liquid glass on/off, watchlist, players marked "taken in my league". | Ratings and pickups depend on league size; personal lists persist with the same guarantees. |
| 2026-10-23 | **Roster sync mounts once** in the root layout (`<RosterSync />`); `AccountButton` is visual only. | The redesign shows the account button in two places (phone and desktop); mounting sync twice would double-save. |

## Database (Supabase)

| Date | Decision | Why |
|------|----------|-----|
| 2026-10-22 | One migration (`supabase/migrations/20261022000000_init.sql`) with RLS on every table; every permission granted explicitly. `scripts/test-db.sh` runs 115 security checks on a throwaway local Postgres. | Plan §9 and §12, provable without a Supabase project. |
| 2026-10-22 | ESPN cookie table: RLS on with no policies and all grants revoked, so only the server can touch it; the browser can only call `my_espn_connection_status()` and `delete_my_espn_connection()`. | Cookies act like a login; they must never reach the browser. |
| 2026-10-22 | Deleting a chat message wipes its text (a moderator copy is kept on reports); `messages.deleted_by` references `auth.users`; rooms are created through `ensure_game_room` / `ensure_league_room`; admins can read every room; blocking is enforced in the database; roster player ids are plain text (no foreign key) because a player may be added before the worker stores him. | Privacy for deleted text; unambiguous joins; rooms can't be spammed; moderation works; no ordering problems. |
| 2026-10-22 | The owner becomes admin once, in the Supabase SQL Editor: `update public.profiles set is_admin = true where username = '…';` | `is_admin` can't be self-granted from the app. |
